# mcd-countdown · 麦麦倒计时

> 你的麦当劳账户里，已经有 **868.3 积分白白过期了**。
> 这个数字不是我编的，是真实账号跑出来的。

把所有会过期的麦当劳资产——券、积分、可兑换商品、限量抢购、抽奖活动——拉成一条时间轴，
告诉你**什么在什么时候失效**，以及**现在还能不能用**。

基于麦当劳中国官方 MCP Server 构建。**只读，不会领券、下单或抽奖。**

---

## 为什么做这个

市面上的麦当劳工具都在回答同一个问题：**怎么买更划算**。

但有一类损失从来没人管：**你已经拥有的东西，正在悄悄过期**。

- 券有有效期，到期作废
- 积分按月清零，过期不可逆
- 积分商城的商品有下架时间
- 限量抢购精确到分钟，错过就没有

这类损失的特点是**沉默**——不推送、不提醒、不显示，等你发现的时候已经没了。

而「损失厌恶」比「帮你省钱」驱动力强得多。看到「已过期 868 分」的反应，
和看到「这单能省 3 块」完全不是一回事。

## 三个别人没挖到的发现

这三个是本项目真正的硬货，都是从真实接口返回里扒出来的。

### 1. 券里藏着「每日可用时段」，但官方把它塞进了一行文本

```
有效期: 2026-10-12 00:00-2026-11-11 23:59 05:00-10:29
```

看到最后那个 `05:00-10:29` 了吗？**这才是每日可用时段**——这是一张早餐券，
下午去根本用不了。官方把它拼在同一行文本里，人眼根本读不出来。

结果就是：领券时不知道，到柜台才发现刷不了。

本项目用可选捕获组把它提取出来，并实时判断「现在可用 / 现在不可用」。

### 2. 麦当劳 MCP 在同一个服务里混用三种返回格式

| 格式 | 涉及接口 |
|---|---|
| 纯 JSON | `query-my-account`、`mall-points-products`、`query-lottery-info` |
| Markdown 包裹 JSON | 带 `# API Response Information ... ## Original Response` 前后缀 |
| 纯 Markdown 报告 | `query-my-coupons`、`campaign-calendar` |

不写统一解析层，下游必然翻车。方案见 `scripts/mcd_mcp.py` 的 `unwrap()`。

### 3. 积分商城必须按「换不换得起」过滤

积分商城返回 35 件商品，但你的积分往往只够换其中几件；而且十几件商品
共用同一个 `downTime`。全量列出只会淹没真正紧急的项。

处理办法：只保留 `point <= 当前可用积分` 的商品，再按截止日合并成一条。

## 安装

需要 Python 3.9+，无第三方依赖（只用标准库）。

```bash
git clone https://github.com/zhangjingjingpangxieyi-ux/mcd-countdown.git
cd mcd-countdown
```

### 申请 MCP Token

1. 打开 <https://open.mcd.cn/mcp>，手机号验证码登录
2. 进入控制台 → 激活 → 同意协议 → 生成 Token
3. 配置到环境变量：

```bash
export MCD_MCP_TOKEN=你的Token
```

或在你的 MCP 客户端配置中加入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer ${MCD_MCP_TOKEN}" }
    }
  }
}
```

完整示例见 `mcp-config.example.json`。

## 用法

```bash
# 终端时间轴（默认）
python scripts/countdown.py

# 结构化 JSON，便于二次开发
python scripts/countdown.py --json

# 生成可视化 HTML 页面
python scripts/countdown.py --html report.html

# 使用示例数据（无需 Token，演示用）
python scripts/countdown.py --demo
python scripts/countdown.py --demo --html demo.html
```

作为 WorkBuddy / Claude Code 等 Agent 的 Skill 使用时，见 `SKILL.md`。

## 只读承诺

本项目**只调用查询类 MCP 接口**，不涉及 `create-order`、`auto-bind-coupons`、`draw-lottery`
等任何会产生副作用的操作。

单次完整采集共 5 次调用，任一失败会输出 `[warn]` 并跳过，不影响其余部分。
